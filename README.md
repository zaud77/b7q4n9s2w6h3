# Build Dispatcher

通过 Telegram 管理 GitHub Actions 构建任务的调度服务。负责用户授权、任务提交、状态跟踪和产物交付，不在服务端执行内核编译。

## 功能

- 校验用户绑定和群组成员资格。
- 保存构建选项，分别调度内核与独立模块工作流。
- 跟踪请求编号及运行状态，将产物发送给请求者。
- 普通用户每个北京时间自然日最多成功构建两次，内核与独立模块共用额度；默认失败不扣次数，可按用户将实际运行的失败构建也计入额度。
- 管理员不受每日额度、冷却和单任务并发限制；同一确认按钮仍只登记一次，普通用户继续限制为一个进行中的任务。
- AOSP 风驰测试入口默认只向管理员显示，按用户单独授权；普通用户仍须完成原有验证并绑定该脚本。

## 管理命令

- `/unbindscript 序列号`：解除对应用户的脚本绑定并清除当前菜单。
- `/unbindscript all`：解除全部用户的脚本绑定；不改序列号绑定、构建偏好、额度或已经提交的任务。
- `/aosptest 序列号或Telegram用户ID`：开放测试入口，同时解除该用户原有脚本绑定，让其重新选择；授权不豁免普通用户的绑定、群组验证或额度。
- `/aosptest 序列号或Telegram用户ID off`：撤销测试权限并清除测试脚本绑定，其他脚本绑定不变。

以上命令仅允许管理员在私聊中使用。

## 运行

生产入口使用 Cloudflare Worker，绑定数据和任务状态保存在 KV 与 D1；Python 客户端用于备用部署。构建目标、访问凭据和服务参数由部署配置指定。

凭据保存为 Secret，不提交到 Git。两个构建入口使用分开的 Secret 配置，不回退到旧账号凭据；迁移时保留现有用户数据和绑定校验材料。

## 检查

```sh
pnpm install --frozen-lockfile
pnpm run check:worker
pnpm run test:worker
```

Python 回归检查使用 `pytest`。部署前检查目标工作流与凭据权限；健康检查用于核对已部署的地址和额度配置，不代替完整构建及设备验证。
